## Contexto já apurado (não precisa re-descobrir, mas confirme no código)

1. **O browser compartilhado do Politron já existe e está pronto.** Ele vive em:
   - `apps/desktop/src/main/ipc/platform-browser.ts` (view visível, BrowserView, partição persistente)
   - `apps/desktop/src/shared/platform-browser.ts` (contrato)
   - `apps/desktop/src/renderer/src/features/panels/PlatformBrowserPanel.tsx` (UI com seletor de agente e botão "Compartilhar com agente")
   - O broker expõe as ferramentas `browser_*` do agente para essa view compartilhada em `apps/desktop/src/main/v9/workspace.ts`.
   - O **browser individual por agente foi REMOVIDO**: `apps/desktop/src/main/v9/browser.ts` não existe mais, o serviço só mantém stubs que recusam ação, e a UI tem uma única aba de navegador, a do Politron ("Navegador", DockTool `web`). Layouts legados com aba `browser` migram para `web` em `dock-layout.ts`.
   - **Não reverta essa remoção.** Não recrie `browser.ts` nem nenhum navegador Playwright por agente. Não crie extensão própria do Politron.

2. **O que falta**: o segundo modo pedido pelo usuário — o agente deve poder usar a **extensão oficial do ChatGPT/Codex no Brave ou Chrome**, para que ele possa verificar uma aba que o usuário já tem aberta (inclusive com sessão logada). O usuário usa Brave.

3. **Peça fundamental já apurada (importante)**: no Codex local, o plugin oficial `chrome@openai-bundled` está instalado e habilitado, e a skill `chrome:control-chrome` aparece em `skills/list` do `app-server` mesmo com a política atual do Politron. O plugin fica em
   `C:\Users\lchen\.codex\plugins\cache\openai-bundled\chrome\26.1021.22027\`
   e traz `scripts/browser-client.mjs`, `scripts/browser-service.mjs`, `scripts/extension-host\`, `scripts/installManifest.mjs`, `scripts/check-extension-installed.js`, `scripts/check-native-host-manifest.js`, `scripts/extension-ids.json`.
   A skill (`skills/control-chrome/SKILL.md`) exige o tool MCP `node_repl` com a tool `js` (executa o `browser-client.mjs`), e o plugin declara hooks no servidor MCP `node_repl`.
   **Hoje o Politron bloqueia isso**: `apps/desktop/src/main/v9/codex.ts` passa `-c mcp_servers={}` e desabilita `computer_use`, `browser_use`, `browser_use_external` e `browser_use_full_cdp_access` por thread, e o `app-server` é iniciado sem servidores MCP.

## Objetivo desta tarefa

Implementar, no Politron, o caminho de **browser externo via extensão oficial**, de forma segura e honesta:

- O agente **não** pode simplesmente reativar `browser_use`/`browser_use_external`/`computer_use` no Codex e achar que isso basta: o que faz a ponte é o servidor MCP `node_repl` + `browser-client.mjs` + `extension-host` do plugin oficial. Ativar flag sem o host não é a integração; se não for possível sem uma ponte real, **não simule**.
- O modo externo deve ser **opt-in explícito por conversa e agente**, com consentimento e revogação, no mesmo espírito do compartilhamento interno: o usuário escolhe o agente e autoriza; o agente não ganha acesso ao navegador do usuário por acidente.
- Deve existir uma forma clara de o usuário **ver** que o modo externo está ativo e de **revogar**.
- Não abrir, ler ou enumerar abas do usuário sem que ele tenha autorizado; não ler cookies, senhas, storage local, perfis ou histórico do navegador; não copiar perfis; não habilitar CDP amplo (`browser_use_full_cdp_access` deve continuar desabilitado).
- Preservar integralmente: o browser interno compartilhado, o modo PWA (sem terminal/PTY remoto, fila como padrão, relay remoto binário desabilitado), o painel "Saída dos agentes" oculto por padrão, e todas as alterações locais já existentes do usuário (NÃO reverta nada, NÃO faça commit nem push).

## Como verificar o que é possível (antes de codar)

Faça uma verificação honesta e **read-only** do caminho real, usando o Codex local:

- `codex plugin list --json` (já confirmado: `chrome@openai-bundled` instalado/enabled).
- Subir o `app-server` local em modo stdio e listar skills/capabilities (já confirmado que `chrome:control-chrome` aparece).
- Inspecione `plugin.json`, `scripts/browser-client.mjs`, `scripts/browser-service.mjs`, `scripts/extension-host\` e os docs do plugin (`docs/`) para determinar **qual** servidor MCP precisa existir, **quais** comandos/ferramentas ele precisa expor e **como** ele se conecta à extensão no navegador (native host manifest). Não invente nomes de ferramentas: use os que o plugin realmente define.
- Verifique se o `node_repl` MCP server está disponível na máquina (`~/.codex/config.toml`, marketplaces, ou se o próprio plugin o empacota). Se o servidor MCP não existir/for instalável de forma simples, **relate isso como bloqueio real** em vez de fabricar uma ponte que não funciona.

IMPORTANTE sobre extensões do navegador: **não** instale nem carregue a extensão do ChatGPT no Brave/Chrome do usuário, **não** leia abas existentes, **não** navegue em páginas reais do usuário e **não** toque em contas. Apenas inspeção de código/config e probes que não abinem a sessão do usuário. Se um passo exigir interação com o navegador do usuário, pare e reporte.

## Requisitos de implementação

- Seguir os padrões existentes do projeto: eventos via `this.emitEvent`, IPC em `apps/desktop/src/main/v9/ipc.ts` com `invokeDesktopOnly` quando aplicável, preload em `apps/desktop/src/preload/index.ts`, contratos em `apps/desktop/src/shared/v9.ts` e `apps/desktop/src/shared/platform-browser.ts`, UI em `apps/desktop/src/renderer/src/features/panels/`.
- Preferência por conversa e agente, persistida, com valor padrão = **não usar browser externo** (o padrão atual do agente permanece inalterado).
- Consentimento e revogação visíveis na UI.
- Fail-closed: se o plugin, o MCP server ou a extensão não estiverem disponíveis, o agente deve receber um erro claro e o app não pode quebrar nem degradar o modo interno.
- Não imprimir nem persistir dados sensíveis (URLs com token/credencial, conteúdo de sessão) nos logs ou eventos.
